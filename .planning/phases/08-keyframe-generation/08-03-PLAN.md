<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Server snapshot -> browser adapter | Authorized durable state becomes a view model; omitted/derived state must not gain authority. |
| Browser controls -> mutation APIs | Selection, generation, and adoption ids are attacker-controlled despite disabled UI. |
| Project tools -> shared configuration/assets | Both stages must edit one authorized Project source without cross-project cache bleed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-13 | Spoofing | viewed/adopted UI state | medium | mitigate | Render adopted id only from snapshot; local state owns viewed/compare ids and cannot write without explicit mutation. |
| T-08-14 | Elevation | hidden/disabled slot controls | high | mitigate | Treat UI disablement as explanation only; Plan 08-02 route/service revalidate every selection and adoption. |
| T-08-15 | Tampering | optimistic React Query state | medium | mitigate | No optimistic pointer/selection updates; await mutation then refetch server snapshot, preserve cache on error. |
| T-08-16 | Information Disclosure | project assets and media refs | high | mitigate | Reuse authorized project hooks/media routes and stable project query keys; do not embed storage/provider secrets. |
| T-08-17 | Repudiation | user adoption action | medium | mitigate | Explicit confirmation calls audited service; UI renders returned server pointer and Task/history metadata. |
| T-08-18 | Denial of Service | dense batch histories | low | accept | Candidate count is server-bounded to four per batch; timeline uses stable lazy media surfaces and horizontal tracks. |
</threat_model>
