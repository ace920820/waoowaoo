# Phase 8 Plan 06：大图预览 + 版本操作

## 目标

让每个新画面对应一个完整的大图预览弹窗，用户可以放大查看、在候选之间切换、下载、重新生成、采用新版本、恢复到上一版本。参考经典分镜页的 ImagePreviewModal + 底部操作条模式。

## 依赖

- Plan 05 的 2×3 布局
- Plan 02 / 03 的生成、采用 API（已有）

## Task 1：KeyframePreviewModal 组件

新建 `KeyframePreviewModal.tsx`：

- 居中大图，保留原始比例
- 顶部：关闭按钮 + 槽位标签（Start / Middle / End）+ 镜头类型角标（可选）
- 底部操作条：下载、恢复上一版本、重新生成 + 候选数选择、查看数据、采用此版本
- 右侧缩略图列：同一槽位所有批次的候选，点击切换预览
- 支持 Esc 关闭、焦点管理、背景遮罩点击关闭

### 验证

- `npm run typecheck`
- 点击遮罩和 Esc 都能关闭
- 打开后焦点在操作条上

## Task 2：新画面卡片接入预览 + 候选切换

- 下排每张新画面卡片点击打开预览
- 预览默认显示当前采用版本（或最新候选）
- 右侧缩略图列按批次分组，显示候选编号
- 点击缩略图只切换预览，显示"正在查看"标识，不改变采用

### 验证

- 切换候选不触发任何 API 请求
- 关闭预览后焦点回到触发卡片
- 采用状态在预览内清晰可见，但不在候选切换时改变

## Task 3：预览操作栏功能

接入已有 mutation 和能力：

1. **下载** — 打开当前预览图片的媒体 URL（新标签页或触发下载）
2. **重新生成** — 调用 `useGenerateRemakeKeyframe`，可选择 1-4 张候选，提交后关闭弹窗并显示 Task 进行中状态
3. **采用此版本** — 调用 `useAdoptRemakeKeyframe`，先弹出确认对话框："将替换当前采用版本，旧版本保留在历史中"
4. **恢复上一版本** — 如果该槽位有多个采用历史事件，则"恢复"就是重新采用前一个版本，走同样的 append-only adoption event
5. **查看数据** — 展开面板显示：Prompt 摘要、生成参数、模型、批次号、候选号、Task ID

### 验证

- 采用和恢复都产生新的 adoption event，不覆盖历史
- 重新生成复用现有接口，不新建路由
- 下载不经过额外服务器请求
- `npm run typecheck`
