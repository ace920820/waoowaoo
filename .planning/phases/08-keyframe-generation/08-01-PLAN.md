<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> internal keyframe API | Authenticated but untrusted ids, slot, operation key, and generation selections enter the server. |
| API -> Task/queue -> Worker | Frozen server-owned input crosses an asynchronous boundary and may become stale. |
| Worker -> model gateway/storage -> database | Provider output and uploaded media become durable candidate/provenance records. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Elevation / Information Disclosure | submission route and candidate relations | high | mitigate | Require project auth and revalidate candidate -> batch -> track -> Shot -> Project ownership in route and service tests. |
| T-08-02 | Tampering | asynchronous Worker completion | high | mitigate | Persist immutable fingerprints and re-read current revision/adopted Prompt inside the append transaction before attaching output. |
| T-08-03 | Tampering | model/options/reference payload | medium | mitigate | Build payload from server facts, strict Zod parsing, centralized capability resolver, and owned reference-asset validation. |
| T-08-04 | Repudiation | generation history | medium | mitigate | Store Task id, Prompt version, frozen options/references, output relation, timestamps, and provenance on every batch/candidate. |
| T-08-05 | Denial of Service | repeated submissions | medium | mitigate | Use canonical fingerprint plus operation-key dedupe and existing queue attempts/concurrency controls. |
| T-08-06 | Information Disclosure | errors/logs | medium | mitigate | Reuse normalized/redacted logging and return stable error codes without provider secrets or signed URLs. |
</threat_model>
