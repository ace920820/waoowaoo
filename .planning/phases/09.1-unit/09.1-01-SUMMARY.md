## Accomplishments

- **Pitfall 1 fixed at the source:** new client-safe `timecodeToSeconds`/`parseTimecodeSeconds` in `unit/timecode.ts`; the keyframe adapter's `durationSeconds` now prefers a numeric timeRange, else parses projected string timecodes, and only falls back to 3 when nothing is parseable — no more silent 3s for every shot.
- **D-09 timed timeline:** `buildRemakeVideoUnitTimeAnchors` scales member durations proportionally to the normalized total T with a floating-point closure assertion (sum of segments == T), and `buildUnitTimedPrompt` emits the cut-declaration header, 总时长 line, and per-member `0-1s（镜头 1）：prompt` lines with 0.1s precision.
- **D-06/D-10 role contract:** `shot_keyframe` added to `VIDEO_REFERENCE_ROLES` and ordered between `end_keyframe` and `action_sheet`; `assertVideoReferenceOrder` relaxed to non-decreasing so N consecutive member keyframes pass while every single-shot ordering guarantee holds; `assertVideoReferencesHaveKeyframe` documents its `_keyframe`-suffix acceptance; labels/usages render and the prompt suffix groups member keyframes under 视觉锚点 without the Start→Middle→End mislabel.
- **D-22 freeze + fingerprint:** strict `videoUnitInputSnapshotSchema` (uuid ids, members ≥2 with per-member keyframe/promptVersionId/timeRangeSeconds, orderedReferences via the existing `orderedVideoReferenceSchema`, `promptText` holding the timed prompt + suffix); `unitInputFingerprint` is sha256 over sorted stable JSON and provably changes on member order / time anchor / keyframe changes.
- **Deterministic descriptor:** `buildVideoUnitTaskDescriptor` returns `TASK_TYPE.REMAKE_VIDEO_UNIT_GENERATE` with `targetType: 'remake_unit'`, `targetId: unitId`, project-mismatch guard (T-091-04), and dedupe key `remake-video-unit:{projectId}:{operationKey}:{fingerprint}`; `parseVideoUnitTaskPayload` strips runtime keys and re-verifies the fingerprint (T-091-02).

## Decisions Made

- **shot_keyframe ordering:** placed between `end_keyframe` and `action_sheet` so member keyframes sort before the merged action sheet; role strings (not order values) persist in rows, so renumbering is safe.
- **Non-decreasing order contract:** `assertVideoReferenceOrder` throws only when a previous role order is greater than the next — admits N consecutive `shot_keyframe` refs with contiguous ordinals while preserving every single-shot ordering guarantee (verified by unchanged remake-video-task-contract tests).
- **promptText in snapshot:** the unit snapshot freezes the full D-09 timed prompt + reference-usage suffix (per-member adopted prompts are merged by the timed-prompt builder upstream); batch-level `promptVersionId` = first member's is deferred to Plan 09.1-03 T3 (research Open Question 1), while members[].promptVersionId stays per-member.
- **Unit descriptor mirrors single-shot:** same shape (taskType/targetType/targetId/inputFingerprint/payload/dedupeKey), same runtime-key strip + fingerprint re-verify, plus reference asserts — single-shot payload schema/descriptor untouched.
- **TASK_TYPE registration ripple:** adding the enum value required entries in the exhaustive `TASK_INTENT_BY_TYPE` and `TASK_TYPE_OWNER_MAP` maps — treated as Rule 3 (blocking) fixes since `npm run typecheck` is the plan's verify.
