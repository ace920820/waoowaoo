## Decisions Made

- **Shared helper location:** a dedicated `src/lib/workers/ark-content-items.ts` module (per the plan's "small shared module" option) rather than exporting from the handler module — keeps the unit handler's import graph light and both handlers provably byte-identical.
- **Unit reference resolver:** a small unit variant (`resolveVideoUnitReferenceStorageKeys(snapshot, actionSheetMediaId?)`) added next to the single-shot resolver — the single-shot signature is untouched (plan preference).
- **No fingerprint drift:** the handler passes the persisted sheet's mediaId into the resolver and hands the ORIGINAL frozen snapshot to `appendVideoUnitBatch`; the deferred marker stays in the persisted batch's orderedReferences while the provider receives the real rendered sheet — required by `appendVideoUnitBatch`'s in-transaction fingerprint re-check (09.1-03).
- **generationMode forced normal:** D-09 units never run firstlastframe; `snapshot.options.generationMode` is ignored and overridden with `'normal'`.
- **Nullable sheet mediaId guarded:** `RemakeVideoUnitActionSheet.mediaId` is `String?` in the schema, so the handler throws `REMAKE_VIDEO_REFERENCE_UNAVAILABLE` if the persisted sheet has no mediaId (never silently resolves the deferred marker).

- **Found during:** Task 2 (GREEN typecheck step)
- **Issue:** `RemakeVideoUnitActionSheet.mediaId` is `String?` in `prisma/schema.prisma`, so `renderAndPersistUnitActionSheet` returns `mediaId: string | null`, which is not assignable to the resolver's `actionSheetMediaId?: string` — and passing null through would silently fail the deferred-marker resolution.
- **Fix:** The handler throws `REMAKE_VIDEO_REFERENCE_UNAVAILABLE` when the persisted sheet has no mediaId before resolving references.
- **Files modified:** src/lib/workers/handlers/remake-video-unit.ts
- **Verification:** typecheck passes; all worker tests pass.
- **Committed in:** ebe3cce (Task 2 GREEN commit)
