## Accomplishments

- **D-06 one-keyframe-per-member collection:** `collectUnitMemberKeyframeCandidates` resolves exactly one adopted keyframe per member (preferred slot default `middle`, falling back to the only adopted slot) through the same `resolveMediaRef` stable-media resolution the single-shot path uses, returns candidates in ordinal order, and fails with a per-member `REMAKE_VIDEO_UNIT_MEMBER_KEYFRAME_MISSING:{ordinal}` when a member has none (D-21 gate material).
- **D-08 cross-member dedup + capped plan:** `dedupeUnitAssetCandidates` collapses the same asset id across members per (role, assetId) — a character keeps one image + one voice candidate while appearing once; `buildUnitReferencePlan` emits shot_keyframes (ordinal) → action_sheet → characters → scene → props → audio and delegates sorting/truncation to the existing `buildRemakeReferencePlan`, so the 9-image / 3-audio caps and the keyframe > action sheet > characters > scene > props > voice degrade are single-sourced and member keyframes are never dropped (T-091-05).
- **D-07 N-grid action sheet:** the sharp cell pipeline was generalized over an ordered source list — `renderActionSheet` now delegates to it with a single column (byte-identical output, pinned by a golden-hash regression test) and `renderUnitActionSheet` lays 2-6 sources in a 2-column grid / 7-9 in a 3-column grid with per-cell 640x360 cover-fit frames and 镜头{N} label bars; `unitActionSheetFingerprint` is deterministic over (renderer version, unit id, ordinal+mediaId list); source count is bounded 2..9 (T-091-07).
- **D-16 WYSIWYG preview:** `buildUnitSubmissionPreview` is a pure, client-safe function (no Node built-in / prisma / storage imports) returning `{ members, orderedReferences, promptText, totalDurationSeconds, referenceCounts }` where the prompt text is exactly `buildUnitTimedPrompt` output and the reference order is exactly `buildUnitReferencePlan` output — what the user previews is byte-identical to what the server freeze consumes; total duration falls back to `deriveDefaultVideoDuration` over the member sum when not supplied.

## Decisions Made

- **Dedup key = (role, assetId):** a character contributes both `character_reference` (image) and `character_audio_reference` (audio) while the same asset appearing in several members collapses to one of each — keying by assetId alone would silently drop either the image or the voice.
- **Grid rule (D-07 discretion):** 2-6 unit sources → 2 columns, 7-9 → 3 columns; cells 640x360 cover-fit + 34px label bar, matching the single-shot cell geometry exactly.
- **Cap truncation single-sourced:** `buildUnitReferencePlan` never re-implements caps — it only orders candidates (keyframes → action sheet → assets) and lets `buildRemakeReferencePlan` sort/truncate, so the degrade priority is provably identical to single-shot.
- **Preview duration:** `totalDurationSeconds` wins when supplied; otherwise `deriveDefaultVideoDuration(memberSum, durationCapabilityDefinitions ?? [])` (client preview gets the ceil + [1,15s] clamp; the server freeze passes real capability definitions).
- **Preview prompt/refs = frozen prompt/refs:** the assembler composes `buildUnitTimedPrompt` + `buildUnitReferencePlan` directly, so the D-16 WYSIWYG guarantee holds by construction, not by duplication.
