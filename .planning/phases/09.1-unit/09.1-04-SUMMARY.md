## Accomplishments

- **D-21 aggregate per-member gate:** `buildVideoUnitSubmission` collects every member's adopted keyframe (via `collectUnitMemberKeyframeCandidates`, per-member try/catch), adopted Video Prompt (`getAdoptedPromptForGeneration`, targetKey video), and legal numeric time range (PARAMS when the payload has no parseable time range at all) — any missing item is appended to a single `REMAKE_VIDEO_UNIT_MEMBER_MISSING:{ordinal}:{KEYFRAME|PROMPT|PARAMS}` error before model resolution or any provider work.
- **D-05 duration policy:** per-member time ranges are parsed to numeric seconds, the raw sum is checked against the model's duration max (capability definitions, default 15s) and throws `REMAKE_VIDEO_UNIT_TOTAL_TOO_LONG:{sum}:{max}` with an explicit 拆分为多个 unit split hint — never a silent truncation; the total then normalizes through `deriveDefaultVideoDuration` and the frozen `durationSeconds` equals the preview's total.
- **D-16/D-22 WYSIWYG freeze:** the frozen snapshot is built from `buildUnitSubmissionPreview` for the exact same member inputs — `promptText`, `durationSeconds`, and `orderedReferences` are byte-identical to the preview, the descriptor fingerprint (unitInputFingerprint) changes when any member keyframe changes, and `assertVideoUnitSubmissionCurrent` re-verifies unit existence / member set / active revisions / adopted-keyframe media equality at freeze time.
- **W5 deferred action-sheet entry:** the frozen `orderedReferences` carries the merged sheet as `action_sheet` with `mediaUrl: 'unit-action-sheet://deferred/{unitActionSheetFingerprint}'` — deterministic and fingerprint-covered; the submission path never renders nor persists (verified by test), the worker (09.1-05) renders+persists via `renderAndPersistUnitActionSheet`, and the preview endpoint renders on demand without persisting.
- **D-04 single-shot membership gate:** `buildVideoGenerationSubmission` looks up `RemakeVideoUnitMember` by the current shotRevisionId at the top of the flow and throws `REMAKE_VIDEO_SHOT_IN_UNIT` — a unit member can never be delivered twice.
- **Merged-sheet persist helper:** `renderAndPersistUnitActionSheet({ projectId, unitId, sources })` renders via `renderUnitActionSheet`, uploads with `generateUniqueKey`/`uploadObject`, ensures a MediaObject, and persists a `RemakeVideoUnitActionSheet` row deduped by `unitActionSheetFingerprint` with member-source provenance in the `sources` column; identical sources reuse the row (no re-render/upload).
- **Authenticated unit API:** `POST /units` (create, 201, D-04 conflict → 409, 401 unauthenticated), `GET/PATCH/POST /units/[unitId]` (detail / userLabel / generate action pinned to this file with submitTask + dedupeKey, error mapping STALE/MISSING/NOT_APPROVED → CONFLICT, NOT_FOUND → 404, INVALID/TOO_LONG → 400), `PATCH /units/[unitId]/members` (pre-freeze, frozen/in-flight → 409), `GET /units/preview` (on-demand `renderUnitActionSheet`, image/jpeg, no persist, bounded 2..9, ownership-scoped), `GET/POST /units/[unitId]/tracks/[trackId]` (note/adopt/reconfirm mirroring single-shot). Every route uses `requireProjectAuthLight` + ownership-scoped service calls (T-091-14).

## Decisions Made

- **Deferred action-sheet marker (W5):** the frozen `orderedReferences` action_sheet entry uses `mediaUrl: 'unit-action-sheet://deferred/{unitActionSheetFingerprint}'` — deterministic, fingerprint-covered, and replaceable by the worker (09.1-05) after render+persist; the snapshot's `members[].selectedKeyframe.mediaId` list IS the deterministic source list the fingerprint covers.
- **D-21 PARAMS semantics:** a member's shot-revision payload with no parseable time range at all (both sides unparseable) is an illegal-parameters gate; partial data falls back to the existing 3s convention (missing end → start+3, missing start → 0) so D-09 anchors never fabricate.
- **D-05 gate placement:** the raw-sum > model-max check fires BEFORE `deriveDefaultVideoDuration` (model resolution must happen first to know the max); the error carries `{sum}:{max}` plus a 拆分为多个 unit hint.
- **Unit asset toggles:** the generate action schema carries no asset toggles, so the unit submission hardcodes the single-shot defaults (character/scene/prop images on, character audio off) — D-08 dedup keeps the 9-image cap.
- **Keyframe slot exposure:** `collectUnitMemberKeyframeCandidates` returns the winning slot so the snapshot's `selectedKeyframe.slot` and `assertVideoUnitSubmissionCurrent`'s track lookup agree.
