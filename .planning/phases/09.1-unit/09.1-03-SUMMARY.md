# Phase 09.1 Plan 03: Unit Persistence Closure Summary

**Durable unit/member/track/batch/version/adoption/action-sheet models with a forward-only migration (D-04 unique membership), the unit CRUD service with a generate-submit member freeze gate and D-22 submission currentness assertion, the idempotent unit batch append + unit-level adoption/note/reconfirm loop, and upstream keyframe/prompt invalidation propagation to unit versions — the complete unit-level persistence closure mirroring the single-shot video spine.**

## Accomplishments

- **D-01/D-04 durable model + forward migration:** seven new `Remake*Unit*` tables mapped to `remake_` prefixes, `RemakeVideoUnitMember` carrying both `@@unique([unitId, ordinal])` and the one-way `@@unique([shotRevisionId])` membership constraint, unit batch `@@unique([trackId, operationKey])` idempotency key, action-sheet `@@unique([unitId, fingerprint])`, and nullable `unitTrackId/unitBatchId/unitVersionId` on `RemakeInvalidation` + `unitBatchId` on `RemakeProvenanceRecord` with relations and indexes — migration is forward-only with no destructive flags, proven by a bootstrapped-DB test that verifies the physical tables and the D-04 constraint in MySQL.
- **D-19 freeze at generate-submit:** `updateVideoUnitMembers` scans the Task table (`targetType: 'remake_unit'`, status queued/processing) inside the transaction and throws `REMAKE_VIDEO_UNIT_GENERATION_IN_FLIGHT` before any batch exists, then `REMAKE_VIDEO_UNIT_MEMBERS_FROZEN` after the first committed batch; add/remove/reorder diffs the member set with an in-transaction D-04 re-check.
- **D-22 currentness + append backstop:** `assertVideoUnitSubmissionCurrent` verifies unit existence, frozen member-set equality (ordinals + shotRevisionIds), active/current member revisions, and adopted-keyframe media equality, throwing `REMAKE_VIDEO_UNIT_INPUT_STALE`; `appendVideoUnitBatch` re-verifies the fingerprint and re-runs the assertion inside its transaction.
- **D-17 unit version loop:** `appendVideoUnitBatch` (idempotent on trackId_operationKey, outputVersion `kind: 'video_candidate_unit'`, provenance with `unitBatchId`), `adoptVideoUnitVersion` (adoption pointer + append-only event + `REPLACE_CONFIRM_REQUIRED` + stale-input check), `setVideoUnitReviewNote`, `reconfirmVideoUnitVersion` (idempotently clears needs_review + output invalidatedAt), and `getVideoUnitTrackDetail` — all ownership-scoped like `getVideoTrackDetail`.
- **D-22 invalidation propagation:** `invalidateRemakeVideoUnitVersions` scans unit batches whose `orderedReferences.mediaId` intersect invalidated keyframe/action-sheet media OR whose frozen snapshot member `promptVersionId` is invalidated, marks only completed unit versions needs_review (T-091-12), creates idempotent `RemakeInvalidation` rows with unitVersionId/unitBatchId, and preserves adoption pointers; the keyframes invalidation hook invokes it under a guard so a shot without a unit never breaks keyframe invalidation.

## Decisions Made

- **Open Question 1 resolution:** unit batch `promptVersionId` = the first member's `promptVersionId`; per-member prompt versions remain in the frozen snapshot `members[]` and drive D-22 propagation by member scan.
- **Member FK policy:** `RemakeVideoUnitMember.shotRevisionId` is a plain column (no FK) — D-04 uniqueness is enforced by `@@unique([shotRevisionId])`; membership queries use the member delegate directly.
- **Adoption stale check:** `adoptVideoUnitVersion` verifies every frozen member revision is still active/current (mirroring the single-shot revision-currency check); adopted-keyframe media equality stays in the append-time `assertVideoUnitSubmissionCurrent` so invalidation/review owns keyframe drift.
- **Unit output evidence spine:** outputVersion carries the first member's shotId/revisionId, `kind: 'video_candidate_unit'`, fingerprint `${operationKey}:${inputFingerprint}:1`, and the provenance record uses schema `remake-video-unit-generation@1`.
- **Invalidation scope:** only completed unit versions are marked needs_review; adoption pointers and history are never touched by the unit invalidation path.
