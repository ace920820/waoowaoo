# Phase 09.1: 短镜头合并 unit 视频生成 - Context

**Gathered:** 2026-08-13
**Status:** Ready for planning

<domain>
## Phase Boundary

本阶段在成片页（`RemakeVideoStage`）为**时长低于视频模型最短生成档位（约 4s）的短镜头**引入"合并 unit"视频生成：用户手动把多个镜头（任意组合，不要求相邻）组成一个 unit，系统把各成员镜头的关键帧（每镜头 1 张）、合并动作表大图、去重资产和带时间锚点的合并提示词，按现有视频模型网关一次提交生成整段 unit 翻拍视频，并完成 unit 级版本审核、备注、采用与上游失效复核闭环。

本阶段只做 unit 的创建 / 生成 / 版本闭环，不实现跨 unit 批量编排（Phase 10）、最终素材导出（Phase 11）和基于同构标签的自动合并建议（已明确取消）。

</domain>

<decisions>
## Implementation Decisions

### 交付单位与合并方式（前几轮设计讨论已锁定）
- **D-01:** 交付单位 = 合并 unit：合并后的一组镜头共用一个翻拍视频，用户直接对整个 unit 审核 / 采用 / 备注，不把生成视频裁剪回单个 shot。 — **Reversibility:** one-way — 数据模型需新增 unit 粒度，Phase 11 完整性检查/导出合同需同步改为 unit 级
- **D-02:** 合并方式 = 纯手动：系统不做默认自动合并，只在用户主动把 >= 2 个镜头加入同一个 unit 时才合并生成。 — **Reversibility:** reversible
- **D-03:** ~~合并方向 = 优先同构相邻镜头~~ **已取消**：不做基于 sceneTag/characterTags 的同构判定与合并建议；合并目标完全由用户手动选择（本次讨论变更）。
- **D-04:** 一个 Shot 只允许属于唯一 unit：某 Shot 一旦加入某 unit，即归属该唯一 unit，不可同时挂到多个 unit；已加入 unit 的 shot 不能再单独生成视频。 — **Reversibility:** one-way — 需在 `RemakeVideoUnitMember.shotRevisionId` 上加唯一约束并迁移既有数据
- **D-05:** MVP 不处理超长镜头：unit 总长上限按现有模型上限（15s）行为一致——超出上限不做自动拆段，只要求用户拆组/接受拉长；超过 15s 的单个长镜头不在本设计范围。

### 参考图与提示词传递（前几轮设计讨论已锁定）
- **D-06:** 每镜头只保留一个关键帧：组内每个镜头贡献 1 张 adopted 关键帧（默认取 middle / 最忠实画面的那帧），作为该镜头时间段画面锚；N 镜头传 N 张，按 sequence 顺序。N 张关键帧 + 合并动作表 + 去重资产必须 ≤ `content[]` 图上限 9。
- **D-07:** 动作表合并为一张六宫格 / 九宫格大图：复用/扩展 Phase 8 的 `renderActionSheet`，把 unit 各镜头按 sequence 顺序铺进 6/9 宫格（每格 = 一镜头的一帧 + 镜头编号），存为 unit 级 action_sheet 输出版本。
- **D-08:** 角色 / 场景 / 物品 / 语音跨镜头去重并入：按 asset id 去重，同一角色只入一次；超上限按关键帧 > 动作表 > 角色 > 场景 > 物品 > 语音降级（音频 cap=3）。
- **D-09:** 提示词合并为一条带时间锚点的分镜时间表：各镜头 adopted Video Prompt 合并为一条，逐镜头标注累计时间区间（如 `0-1s 镜头1；1-4s 镜头2`），头部声明多镜头 cut 切换、非连续运镜；时间区间按成员时长占比缩放适配归一化后的总时长。 — **Reversibility:** costly — 涉及提示词模板与时间锚点纯函数，调用面广但可回退
- **D-10:** 契约调整：现有 `assertVideoReferencesHaveKeyframe` 只认 `*_keyframe`(start/middle/end)，unit 需在 `reference-roles.ts` 扩展每成员角色（如 `shot_keyframe`）或调整排序/抽查函数。

### 短镜头兜底策略（本次讨论）
- **D-11:** 允许单独生成兜底：短镜头可以不进 unit，单独生成时按现有 `deriveDefaultVideoDuration` 逻辑拉长到最短档（如 4s）。
- **D-12:** UI 明确标注拉长：单独生成的短镜头在成片页标注"拉长到最短档"，用户清楚知道时长被注水。
- **D-13:** 兜底提示词不声明扩展：单独生成兜底时不加"原时长 vs 生成时长"的特殊说明，保持简单。

### 成片页交互（本次讨论）
- **D-14:** 入口 = 单 shot 页内勾选切 unit：成片页顶部保持单 shot 视图，另加"合并 unit 模式"入口；用户勾选多个镜头后进入 unit 视图。
- **D-15:** 成员任意组合：unit 成员不要求相邻（sequence 连续），允许任意镜头组合；用户自己负责顺序合理性，提交时按勾选顺序生成。
- **D-16:** 完整预览面板：unit 视图展示成员镜头顺序列表（含时长）+ 参考图顺序预览（每镜头 1 帧 + 合并动作表大图）+ 时间锚点提示词预览 + 总时长/参数，提交前所见即所得（对齐 VGEN-02 / D-05 语义）。
- **D-17:** unit 级版本闭环：unit 有独立版本列表，沿用现有 batch/version/采用/备注/失效语义；播放 unit 整段视频，采用指针在 unit 级。
- **D-18:** 成员状态 = 显示 unit 归属并可跳回：已加入 unit 的成员在单 shot 视图显示"由 unit 交付"，视频区隐藏/禁用单 shot 生成，点击可跳回 unit 视图。
- **D-19:** 提交前可调、提交后冻结：提交前可增删/重排成员，提交生成后 unit 成员冻结（不可改，只能重新生成或重建 unit）。
- **D-20:** 时长不足提示：系统保留"镜头过短（< 最短档），建议并入相邻镜头或接受拉长"的提示引导，但不自动指定合并目标（取代原同构建议）。

### 门禁与校验（对齐 VGEN-07）
- **D-21:** unit 组内任一成员缺少已采用关键帧 / 已批准 Video Prompt / 合法参数时，阻止该 unit 生成并逐成员说明原因。
- **D-22:** unit 输入快照沿用不可变冻结 + `videoInputFingerprint` 去重语义；任一成员/时间锚变化会改变指纹；上游（Prompt/关键帧）变化利用现有 provenance/invalidation 传播到 unit 版本复核状态（对齐 D-17 语义，作用范围是 unit）。

### the agent's Discretion
- 时间锚点区间计算的具体纯函数实现位置（时长占比缩放算法）。
- 合并动作表大图渲染的具体尺寸/布局细节（6 vs 9 宫格的选择规则）。
- unit 视图在成片页的具体布局排版与勾选交互细节（checkbox 选择形态、进入 unit 视图的方式）。
- `RemakeVideoUnit` / `RemakeVideoUnitMember` 与 unit track / batch / version 的精确 Prisma 模型拆分，只要满足追加历史、稳定引用、明确采用和完整 provenance。

</decisions>

<specifics>
## Specific Ideas

- 用户明确要求：合并完全手动，系统不做任何自动合并建议（不做同构判定），只保留"时长不足"提示引导。
- 参考图传递的核心约束是 `content[]` 图上限 9：unit 参考图 = 每镜头 1 关键帧 + 1 合并动作表大图 + 去重资产，必须 ≤ 9。
- 提示词是"带时间锚点的分镜时间表"：`0-1s（镜头1）：prompt1；1-4s（镜头2）：prompt2`，头部声明多镜头 cut 切换。
- 提交前所见即所得：用户看到的参考图顺序、时间锚点、提示词、参数 = 模型实际收到的。

</specifics>
