# Phase 7 前端需求：Prompt 分析与人工审核

**状态：** 可交给前端开发
**位置：** 视频翻拍工作台内的“Prompt 分析”阶段
**目标：** 让用户能看着原视频和关键帧，手动发起 Prompt 分析、审核内容、保留版本并批准后续生成要使用的版本。

## 1. 页面边界

- 在现有 `RemakeWorkbench` 阶段导航中新增“Prompt 分析”，不建立独立产品页面。
- 页面只处理图片 Prompt 和 Video Prompt 的分析、查看、编辑、版本与审核。
- 不在本页面提供图片生成、视频生成、最终导出或自动分析全部关键帧。
- Codex CLI 始终由后台 Task/Worker 调用。前端只发起任务、读取状态和展示结果，不显示或拼接 CLI 命令。

## 2. 整体布局

### 顶部状态栏

保持现有 Waoo 项目栏和阶段导航。在 Prompt 阶段正文顶部增加一条紧凑状态栏，包含：

- 当前可分析 Shot 数量、待审核数量、已批准数量和失败数量。
- “分析整段视频”主按钮；已有结果时文案改为“重新分析整段视频”。
- 最近一次整段视频分析的状态和时间。
- 任务运行时仍允许浏览、编辑和审核其他已有结果。

### 主体区域

桌面端使用稳定的左右布局：

- 左侧为 Shot 列表，建议宽度 280-320px。每行显示 Shot 序号、时间范围、图片 Prompt 完成数、Video Prompt 状态和审核状态。
- 右侧为当前 Shot 的详情区，顶部显示 Shot 序号、时间范围、原视频片段播放入口和上游审核状态。
- 详情区使用两个页签：“图片 Prompt”和“视频 Prompt”。页签切换不改变当前 Shot。
- 小屏幕下 Shot 列表改为可打开的抽屉或顶部 Shot 选择器，详情区单列展示。任何按钮、状态文字和 Prompt 内容不得横向溢出。

不要把整个页面拆成层层嵌套的卡片。状态栏、Shot 列表和详情区应是清楚的工作区域；仅版本条目或弹窗可以使用独立卡片。

## 3. 图片 Prompt 页签

### 三个关键帧

按 Start、Middle、End 展示三个固定位置。每个位置独立包含：

- 原始关键帧大图，可点击查看原图。
- 当前状态：未分析、排队中、分析中、待审核、已批准、失败、需要复核。
- “生成图片 Prompt”或“重新分析”按钮。
- 已有结果时显示版本入口和当前采用版本。

三个位置可以分别操作。不得提供“全部生成”按钮。

### 任务反馈

- 用户点击一张关键帧后立即显示“排队中”或“分析中”，并禁用该图片的重复提交按钮。
- 用户可以继续点击其他关键帧。后台最多同时运行 3 个，超出的显示“排队中”。
- 一个任务失败不影响其他图片任务；失败位置显示简短、可理解的原因和“重试”按钮。
- 页面刷新后必须从后台状态恢复，不得把仍在排队或运行的任务显示成未开始。

### 结果展示

默认结果区按下面顺序展示：

1. “整合生成提示词”：可阅读、可进入编辑状态的主要文本。
2. “负面约束”：独立区域展示，可阅读、可进入编辑状态。
3. “查看完整分析”：默认收起，展开后显示完整 Skill 输出，包括分析依据、结构化提示词、整合生成提示词、负面约束和当前 Skill 返回的待确认项。

完整分析较长时应在页面内部自然展开，不使用很小的滚动文本框。原始输出无法解析时，仍应允许用户在完整分析中查看原文，同时明确提示“部分内容未能整理”。

## 4. Video Prompt 页签

### 整段分析入口

- Video Prompt 只有项目级“分析整段视频”入口，不为单个 Shot 提供单独分析按钮。
- 点击后启动一次后台任务。该任务读取整段原视频、全部当前已确认 Shot 边界和每个 Shot 的 Start/Middle/End 关键帧。
- 页面显示一个整体任务状态。成功后，各 Shot 同时得到本次分析对应的新版本；失败时本次不出现任何半成品版本。
- 失败后可“重试整段分析”，已有旧版本和旧批准状态保持不变。

### 当前 Shot 结果

右侧详情主要显示当前 Shot 的“核心内容描述”，要求简短、容易修改，重点说明镜头里发生了什么。

结构化内部结果放在“查看详细分析”折叠区，供需要时检查动作、人物互动、方向、调度、机位、镜头运动、节奏、环境变化和时间推进。主界面不要用这些详细字段淹没用户。

## 5. 编辑、版本和审核

图片 Prompt 的每张关键帧、Video Prompt 的每个 Shot 都分别执行以下规则：

- 自动生成的新版本默认标记为“待审核”。
- 用户对当前内容满意时，可以不修改直接点击“批准”。
- 点击“编辑”后进入明确的编辑状态，提供“保存为新版本”和“取消”。保存不得覆盖原版本。
- 已批准版本显示“当前采用”标记。
- 新待审核版本生成后，旧的已批准版本继续显示为“当前采用”；新版本只有批准后才替换它。
- “版本记录”打开版本面板，按新到旧显示版本号、来源（自动分析/人工编辑）、创建时间、审核状态和当前采用状态。
- 选择历史版本只切换查看内容，不自动改变当前采用版本。改变采用版本必须通过明确的“批准并采用”操作。
- 被上游 Shot 边界或关键帧修改影响的版本显示“需要复核”，不能继续作为默认生成输入，直到用户重新确认或批准合适的新版本。

关键操作应使用清晰按钮：批准使用确认图标加文字，编辑使用编辑图标，版本记录使用历史图标，展开使用折叠箭头。仅图标按钮必须有 tooltip 和可访问名称。

## 6. 必须覆盖的页面状态

- **没有原视频：** 告知用户先回到视频分析阶段导入视频，并提供返回入口。
- **没有 Shot：** 告知用户先完成镜头识别。
- **Shot 未确认或关键帧不完整：** 显示缺少的条件，并禁止对该项发起分析。
- **从未分析：** 显示清楚的首次操作按钮，不展示空白编辑器。
- **排队/运行：** 显示真实任务状态；没有可靠进度时使用不确定进度，不伪造百分比或剩余时间。
- **失败：** 显示用户能理解的错误摘要和对应重试入口；详细技术信息放在 Task drawer。
- **待审核：** 明确提示结果尚未允许下游使用。
- **已批准：** 显示当前采用版本及批准状态。
- **新旧版本并存：** 同时看得出“正在查看的版本”和“当前采用的版本”，两者不能混淆。
- **需要复核：** 说明上游内容已变化，旧 Prompt 被保留但暂不可默认使用。

## 7. 数据与接口展示要求

前端需要从后端获得并正确展示：

- Shot 稳定 ID、序号、时间范围、当前 revision 和是否满足 Prompt 分析条件。
- Start/Middle/End 各自的媒体地址、图片 Prompt 当前采用版本、最新版本和关联 Task。
- 每个 Shot 的 Video Prompt 当前采用版本、最新版本和整段分析 Task。
- 每个版本的版本号、自动/人工来源、主要内容、完整内容、审核状态、采用状态、创建时间和 provenance 摘要。
- Task 的排队、运行、成功、失败、取消状态及可理解错误。

前端不得用本地状态猜测“已批准”或“当前采用”。提交成功后以服务端返回和重新查询结果为准。

## 8. 前端验收流程

Phase 7 前端至少通过以下实际流程后才能合入：

1. 进入已有原视频和已确认 Shot 的翻拍项目，打开“Prompt 分析”阶段。
2. 连续点击至少 4 张不同关键帧，看到最多 3 个运行、其余排队，并最终分别得到结果。
3. 图片结果默认突出显示整合 Prompt 和负面约束，完整分析可展开。
4. 不修改一个图片 Prompt 直接批准；编辑另一个并保存为新版本后批准。
5. 发起一次整段 Video Prompt 分析，成功后切换多个 Shot 查看各自的核心内容描述。
6. 重新分析整段视频，确认旧批准版本在新版本待审核期间仍然有效。
7. 分别批准某个 Shot 的 Video Prompt 和某张关键帧的图片 Prompt，确认其他项不会被连带批准。
8. 模拟图片任务失败和整段视频任务失败，确认错误、重试和旧版本保留行为正确。
9. 刷新页面，确认任务、版本、采用状态和审核状态都能恢复。
10. 在桌面和移动宽度检查 Shot 导航、长 Prompt、按钮和状态标签无重叠或横向溢出。

## 9. Phase 7 完成门槛

- 前端实现已经合入主项目，而不是只存在于外部开发分支或设计稿。
- 上述验收流程通过，并覆盖至少一条真实后台 Codex CLI 分析路径。
- 未批准 Prompt 无法成为 Phase 8/9 默认输入；批准后能够被后端准确读取。
- 页面没有提供自动批量分析全部关键帧，也没有绕过后台任务直接调用 Codex CLI。
